対象条件・公開URLと移行順は [common-spec-migration.md](common-spec-migration.md) を参照。この変更の計画は、(1) 既存の採点/識別値を維持した表示翻訳、(2) 任意名と結果単位の再送、(3) 読み取り状態と音設定、(4) モック通信での検証、(5) PR更新。実装は `index.html` の単一配信を維持する。

## 維持するゲーム・保存契約

- `game_slug=anatano_1byou`、同じSupabaseプロジェクト、同じ既存スコア集計。合計誤差が小さいほど良い (`asc`)、scale 100、表示2桁。各タップを小数2桁に丸め、目標との差を足す既存の順序を維持する。
- 目標3個、6〜30秒、間隔4秒以上、可視時計3秒、制限40秒、開始前3秒+650ms、正常終了後1秒の案内。正常終了は3回のタップが揃ったときだけ。時間切れ/リタイアはスコアを投稿しない。
- 端末の自己ベスト `anatano_1byo_best_score_v1` と前回結果 `anatano_1byo_last_result_v1` を変更・消去しない。前回結果の既存日本語値は読み込み時に表示用へ変換するだけ。
- 名前は `anatano_1byou_player_name_v2` に保存する。初回読み込みだけ従来の共有キー `chameleonjp_player_name_v1` を参照し、旧キーを消去しない。新キーに空文字がある場合も有効な消去操作として優先する。他ゲームの共有名を上書きしない。
- 既存のサーバー参加者識別は正規化した表示名。**同名別人の分離・改名時の本人継続は未解決**。このPRで過去記録の所有者を推定したり、新IDへ移し替えたりしない。結果一覧にも同名だけを理由に「あなた」と付けない。

## 任意名・再送とDBの前提

ホームに名前入力と「入力すると名前と記録が公開される・空欄でも遊べる」説明を置く。空欄/空白は非公開で遊べ、結果・ランキング・X共有を使える。20 Unicode文字までを確認し、IME確定中のEnterでは開始しない。名前・クライアント版・UUIDは開始時に固定し、以後の入力変更をそのプレイへ持ち込まない。匿名の過去プレイは後から送信しない。このゲームには既存の匿名開始RPCはなく、新しい匿名記録は作らない。

**マージ前の依存:** [実験場PR43](https://github.com/chameleonjp-lab/chameleonjp_lab/pull/43) の `docs/chameleonjp-lab/sql/common-score-receipt-v1.sql` にある `public.submit_score_once_shared_v1` を、同PRの適用/読み戻し手順で適用する必要がある。SQLのPGlite検証は実験場側で実施。本番へはこのPR作成時点で未適用。現在の旧 `submit_score` は残り、既存公開版に影響させない。

新クライアントは同じ既存 `submit_score` 集計をトランザクション内で一度だけ実行する上記ラッパーを使う。未適用/通信失敗時は待機し、旧RPCに切り替えて二重登録を起こさない。RPC失敗の結果表示をランキング読込成功で上書きしない。全RPCは10秒で中断でき、再送操作が永久に待機しない。

確定時に `anatano_1byou:score-pending:v1:<UUID>` へ名前・点数・版・結果を保存してから送る。複数の未送信プレイを別キーで残す。オンライン復帰・再読込・再試行は同じUUIDと値で行う。成功応答の名前・整数スコア/回数・重複フラグを確認して、そのIDだけ削除する。不正なデータや永久拒否は保存したまま自動再送しない。名前等の設定や自己ベストは消さない。

`anatano_1byou_result_v2` は直近の結果表示用。最後のタップ確定時、1秒の結果案内の前に保存する。再読込は保存結果を表示して、既に存在する待機項目だけ再送する。表示スナップショットから新しい送信IDは作らない。保存領域が拒否/満杯の場合は同じタブ内の保持のみになり、再読込後の保持は保証できない。ブラウザ終了時に保存データを消す設定にも同じ制約がある。

## ランキングと共有・画面

既存 `get_best_score_ranking` と `get_first_try_ranking` の参加者集計結果を各最大30件表示する。`rank_no` を優先し、同点を表示順で順位付けしない。同名行のクライアント側削除はしない。表示境界の順序は既存RPCに従う。上位30から圏外本人順位や参加者数を推測しない。ホームの人数/回数は既存 `get_game_play_stats` が返した値だけを使う。

通信中・空・失敗・再取得を表示。成功送信後に読み直し、世代番号で古い読み取りを無視する。読み込みは送信成功を待たず開始する。操作ボタンを長い順位表の前へ移動し、翻訳でホームが長くても縦スクロールできるようにする。共有/ランキングは44px以上、長いボタン名とプレイヤー名を折り返す。

ホーム/結果の黒地白字Xボタンは投稿確認画面を開き、失敗時にコピー可能な本文を残す。結果共有は今回の確定値で、名前・推測順位・参加者IDを入れない。正式URLの切替前なので、共有するURLは現在の実験場登録URL `https://chameleonjp.codeberg.page/anatano_1byou/` のまま。

## 効果音実装表

音源はWeb Audioの生成音。音量初期値0.3、短い包絡線で立上り/終端を抑える。実際の音量・聴こえ方は未聴取。

|イベント|役割/条件|重複抑制|実装|

## 2026-11-02 後続確認と修正

今回の基点は PR3 `b55141de048ac1fb14913e582bae64e0e955d865`、main `386b3339c1bcbda9ee142d724ac16c89a50d848f`。03:50 JSTに現在のCodeberg公開ホーム「あなたの1秒って」の説明・開始/共有ボタンをブラウザで確認し、実験場の現登録もactive/shared、昇順、scale100、小数2桁、同Codeberg URLのまま読取専用で再照合した。公開先ではプレイや試験スコア送信を行っていない。上記の過去確認を今回の実施と読み替えず、今回差分を以下に記録する。

- 未保存のreceiptは送信しない。容量・保存拒否から回復した際は各プレイの元UUID・名前・値を保ったまま保存して送る。表示結果の保存も全文読み戻しで確認し、失敗時は全15言語で画面を閉じると失われ得る旨を表示する（91文字列）。
- 同UUIDに別payload、キー/ID不一致、壊れた値があれば元データを上書き・削除せず送信停止。他の正常なプレイは継続。受理済みreceiptは送信済み印を残し、再確定・再読込で新しい送信にしない。保存失敗後の再読込は元UUIDを再送し、サーバーの重複照合が必要。
- 応答はnormal RPC契約の1行配列・受理値・2つの名前・整数スコア/登録回数・3 booleanを照合する。不完全ACKは保留。現DBのnormalize/表示名はともにbtrimであることを03:37 JSTに読取専用定義照合した。旧first/bestのsigned integerを勝手に再判定しない。応答に今回のUUID/スコア全payloadは含まれず、完全なpayload読戻しとは扱わない。
- interrupted/suspended時の予約音を停止。stop/disconnect例外でもgainを後片付けし、復帰時に古いイベントを再生しない。既存5イベント・初回0.3・保存off/0は維持し、秒を知らせる音は追加しない。
- PR検証を全unitとChromium/WebKitへ拡張し、mainマージ後だけ同コミットの検証済み成果物を公開する既存条件を維持。非空のローカル配信出力は自動削除/上書きせず停止する。

40秒上限、3目標、6〜30秒・4秒間隔、最初の3秒だけ時計表示、タップの2桁丸めからの合計誤差、scale100/昇順、自己ベストと旧名前/結果キーは維持。時間切れ/リタイア/guestを公開スコアへ変換しない。ブラウザ試験はSupabase全通信をモックし、本番記録は作らない。WebKitの自動試験はiPhone Safari実機受入・実音聴取ではない。
